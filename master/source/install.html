Installation

Installation procedure

To install ATLAS, you can use pip in a python virtual environment or conda environment. ATLAS requires python3.12 or newer, which can be installed through the OS’s package manager or conda.

1. Creating a python environment

First, create a virtual environment and activate it. This can be done in several ways, but we provide some examples using conda, python venv or uv.

Option A - conda

# Create a conda environment named atlas which uses python 3.12
conda create -n atlas python=3.12

# Activate the environment
conda activate atlas

Option B - venv

An example for an Ubuntu 24.04 system, using python3.12 and venv:

# Install python3.12 and venv
sudo apt install python3.12 python3.12-venv

# Using python venv - create and activate the environment
python3.12 -m venv atlas
source atlas/bin/activate

Option C - uv

First, install the uv tool. Either as shown below using the standalone installer, or please refer to the official uv installation guide for more options.

wget -qO- https://astral.sh/uv/install.sh | sh

Once uv is installed, create an environment named atlas specifically with Python 3.12:

# Create the virtual environment
uv venv atlas --python 3.12

Make sure to navigate to a folder where you would like your python environment to be located, or specify the desired path. You can activate the newly created environment as follows:

source atlas/bin/activate

With the environment now activated, the library can be installed.

2. Getting the ATLAS code

# Clone the repository
git clone https://github.com/pol-sb/atlas.git

3. Installing the library in the activated python environment

There are several installation mechanisms, and several optional dependencies depending on what packages you want to use. Check the list and details of optional dependencies in the pyproject.toml. Currently, the following are available:

  • mace — MACE model training and evaluation

  • allegro — Allegro model support (via nequip-allegro)

  • nequip — NequIP model support

  • orb — Orb pretrained foundation potentials (inference only, via orb-models)

  • dev — Development dependencies (pytest, pre-commit, commitizen)

  • gui — Desktop GUI (PySide6)

[!NOTE] fairchem is not a pip extra: fairchem-core requires numpy>=2, which conflicts with the numpy<2 pin in the base dependencies. Install it directly in a dedicated environment or container.

[!NOTE] EquiformerV3 is inference-only and is not a pip extra: it requires the OCP-era fairchem fork bundled with atomicarchitects/equiformer_v3 (it provides the OCPCalculator API removed from fairchem-core 2.x). Follow that repository’s environment setup, then select it in ATLAS with md_type = "equiformer:mptrj_gradient".

Optional dependencies are installed using the following syntax:

python3 -m pip install ./ATLAS['OPTIONAL_DEPENDENCY_NAME']

Some installation examples follow:

[!WARNING] Each MLIP framework needs its own environment. The backends have mutually incompatible dependency stacks — for example MACE (mace-torch) pins e3nn==0.4.4 while Allegro/NequIP need e3nn>=0.6, and Orb plus fairchem (installed separately) require numpy>=2 against ATLAS’s numpy<2. Install one framework per virtual environment. For a single active-learning run that mixes backends (e.g. training with MACE, MD sampling with Orb), run each backend from its own container image via the per-backend container_settings.

[!IMPORTANT] Match the PyTorch build to your NVIDIA driver. The default PyPI torch wheels target the newest CUDA release (CUDA 13 for torch 2.10+), which needs NVIDIA driver 580 or newer. On an older driver, torch.cuda.is_available() returns False, or importing torch fails with undefined symbol: ncclCommResume. Check your driver’s CUDA version with nvidia-smi, then install a matching build as shown below. The mace extra also pulls cuequivariance-ops-torch-cu12, which expects a CUDA 12 torch build.

Using pip

# Install a CUDA 12 build of PyTorch first (pick cu126/cu128/cu129 to match nvidia-smi)
python3 -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu129

# Install the library and the MACE dependencies in the venv using pip
python3 -m pip install "./ATLAS[mace]"

Using uv

uv can detect the installed driver and select the matching PyTorch index automatically:

# Install the library and the MACE and dev dependencies using uv
uv pip install --torch-backend=auto "./ATLAS[mace,dev]"

Verify that the GPU is visible with python -c "import torch; print(torch.cuda.is_available())".

Using the uv lockfile

The repository ships a uv.lock that resolves the mutually exclusive backend extras in separate forks. This workflow requires Python 3.12 or newer:

uv sync --extra mace

uv sync creates a local .venv by default. To install into an already-activated Python 3.12 environment, use uv sync --active --extra mace. Install only one training backend per environment (mace, nequip, or allegro); the [tool.uv] conflicts in pyproject.toml reject incompatible combinations. On Linux x86_64 the lockfile selects the CUDA 12.9 PyTorch build, which works with drivers older than 580. On other platforms, use the uv pip install --torch-backend=auto command above if the default PyPI build does not match your driver.

Installing the GUI

The ATLAS Hub desktop GUI requires the optional gui dependency:

python3 -m pip install "./ATLAS[gui]"

4. Initialize configuration files

Finally, initialize configuration files by running the initial configuration command (atl_init_setup). Then, enter your Materials Project API key in the path displayed in the output to finish the setup process:

# Run the last setup step - configuration initialization
atl_init_setup

[!NOTE] If the user is only interested in database generation, the setup can be completed only up until this point, skipping the following AiiDA setup.

5. Setup steps specific to active learning

  • The active learning (AL) loop uses the AiiDA library for managing the workflow. In order to run the AL loop in compute clusters, codes and computers must be conifigured in AiiDA. See the AiiDA installation guide for installation instructions.

  • DFT calculations with VASP use the aiida-vasp plugin, which needs additional configuration. Please, follow the instructions on their website.

  • The steps required to set up the active learning loop with the simplest AiiDA configuration are the following:

    1. Set up an aiida profile and database with verdi presto.

    2. Create the AiiDA computer and code entries for ATLAS and aiida-vasp.

    3. Add the potential datasets for aiida-vasp (information here).
